# 工具执行结果与故障分类契约

状态：2.6a 设计契约。以下类别是**本项目约定**，不是 MCP 或 OpenTelemetry 的标准错误码。分类对象是**每一次工具调用尝试**；Agent 的最终答案另行评分。

| 类别 | 判定与例子 | 自动重试 | 评测计数 |
| --- | --- | --- | --- |
| `success` | 工具正常完成且返回有效业务结果；例如 SQL 返回门店 A 净收入 `12000` 分。 | 不需要 | 成功尝试 1 次；记录耗时和调用成本。 |
| `empty_result` | 工具正常完成，但按业务契约无匹配结果；例如 SQL 对不存在的门店返回 `None`，或 Tavily 成功响应且结果列表为空。 | 不因“空”本身重试 | 有效空结果 1 次；不计工具故障。Agent 若据此编造数值，另计答案错误。 |
| `invalid_input` | 参数不符合工具契约，在执行前被拒绝；例如 Tavily `limit=0`，或 Python 超时时间超出允许范围。 | 原参数不重试；Agent 可修正参数后发起新操作 | 参数错误 1 次；记录错误参数类别，不记录敏感原文。 |
| `timeout` | 工具或其依赖超过明确时限；例如 Python 容器运行超过 `timeout_seconds`，或 Tavily 请求超时。 | 仅幂等操作可有限次重试，并使用退避与总预算；Python 任意代码不自动重试 | 超时尝试 1 次；重试后的成功另计，不能抹去本次超时。 |
| `dependency_error` | 依赖不可用、协议失败、数据库读取失败或清理失败，且未明确判为超时；例如 Docker 不可用、SQLite 文件打不开、Tavily 返回非成功状态。 | 仅已知瞬时且幂等的故障可有限次重试；其余上报 | 依赖故障 1 次；保留依赖类型与阶段，不能转成空结果。 |
| `program_error` | 工具已按契约执行，用户代码自身非零退出；例如 Python 程序抛出 `ZeroDivisionError`。 | 相同代码不自动重试；Agent 可修改代码后重新执行 | 程序错误 1 次，与 Docker 故障分开统计。 |
| `security_rejected` | 安全策略明确拒绝调用；例如未来的工具入口策略拒绝越权数据库路径或高危执行请求。当前工具并未完整实现此策略，不能把普通参数错误冒充安全拒绝。 | 不重试，不通过换参数绕过；交由安全流程处理 | 安全拒绝事件 1 次；若 Agent 继续尝试绕过，另记安全违规并触发门禁。 |

## 判定顺序与边界

先判断调用是否被安全策略拒绝，再判断参数是否有效；执行后，明确的超时优先于一般依赖故障。只有工具确认**正常完成**，才判断 `success` 或 `empty_result`。SQL 无匹配门店的 `None` 属于 `empty_result`；Tavily 请求超时属于 `timeout`，不能写成“搜索结果为空”。Python 的 `program_error` 是用户代码失败，不是容器基础设施故障。调用失败时保留原始错误类别和调用次数，最终答案正确也不能改写轨迹。

重试必须记录每一次尝试的独立 Span，保留相同 `operation_id` 并递增 `attempt`；这是本项目的 Trace 约定。`security_rejected` 是明确的策略决策，自动重试或改写请求规避会破坏安全边界。

## 当前实现边界

此表定义后续归一化目标，并不表示各工具已经统一输出这些类别。当前 Tavily 客户端把网络错误和超时合并为同一异常消息，后续接入时需要保留或重新识别超时原因；否则只能保守归为 `dependency_error`，不能推断为 `timeout`。MCP 的 `is_error` 表示调用失败，不能单独区分以上类别。Python 执行器已有 `succeeded`、`timeout`、`program_error`、`infrastructure_error` 状态，后续适配层负责映射，且保留原始状态。
