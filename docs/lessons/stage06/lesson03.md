## 方法论

多裁判不是把同一个模型调用三次就宣称“三人独立”。本课要求三个不同的裁判 ID 和模型实例，逐名按同一固定 Rubric 评回答清晰度，并保留每票分数、理由、模型 ID、Rubric 哈希与用量。三票齐全且至少两票相同才形成多数结论；三种分数各一票为 `disagreement`，任一调用失败为 `incomplete`，两者都交人工复核。多数票只反映裁判间共识，**不能覆盖 Code Evaluator 的正确性或安全门禁**。

即使三个实例都投同一票，若来自同一基座或共享提示词，也可能有相关偏误。真实评测应记录模型供应商和版本，优先使用异构裁判，并在 6.5 以人工参考标签校准；投票不能替代人工。Anthropic 的评测实践强调明确 grader 标准和人工校准；这里的三票门槛是本项目工程选择。[Anthropic Agent Evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

## 实践目标与验收

教师实现 [run_judge_panel](../../../src/merchant_agent/evaluation/judge_panel.py)。输入 Trial、Code 评分、三个独立 JudgeSpec；输出原始票、分歧比例、状态、是否需人工复核和未被改写的 Code 通过状态。专项测试覆盖 2/3 多数、三方分歧、单裁判失败与重复 ID。[真实试点](../../reports/judge_panel_challenges_2026-11-03.md)在六条已双标的虚构挑战上各调用同一 DeepSeek 模型三次，18 票全部有效，六题都是 3/3 同票且与人工参考分一致。此试点只证明同模型调用的执行链路，不等于异构独立裁判或真实业务分布校准。

## 面试考点与踩坑

问：两票相同为何不一定可信？答：裁判可能共享训练偏差或提示词偏差。问：裁判失败能否用剩下两票通过？答：本项目不能；预设三票协议缺一票即不完整。问：为何保留少数票理由？答：它可能发现 Rubric 歧义或多数票遗漏的证据。问：投票结果能否覆盖安全违规？答：不能，安全红线独立一票否决。
