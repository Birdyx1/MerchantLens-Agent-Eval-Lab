## 方法论

Agent 有随机性，一道题运行一次只能得到一个观测值。应先冻结 Task、环境、模型与 Harness 版本，预设每题重复次数；失败和超时同样计入分母，不能只重跑失败题直到成功。Anthropic 的 Agent eval 方法强调多次 Trial 与结果分布；本课的区间算法是项目工程选择。[Anthropic Agent Evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

本课区分两层不确定性：**同题运行波动**用成功次数/重复次数及 Wilson 二项区间；**跨题泛化波动**先求每题成功率，再按 Task 等权平均，使用固定随机种子的 Task 级 Bootstrap 给出描述性区间。不能把同一道题的三次 Trial 当作三道独立题来缩窄跨题区间。只有一道 Task 时，跨题区间为 `null`。小样本区间很宽，不能据此声称版本显著提升。

## 实践目标与验收

教师实现 [重复试验统计](../../../src/merchant_agent/evaluation/uncertainty.py)：输入 5.3 的 Trial 指标、预设重复次数、置信水平与 Bootstrap 种子；输出逐题成功率、Wilson 区间、等权宏平均和 Task 级 Bootstrap 区间。拒绝重复 Trial ID、非布尔成功标记和每题重复次数不齐。固定种子使报告可复算；它不会让模型输出本身变得确定。

专项测试覆盖区间边界、输入顺序不影响结果、单题不报告跨题区间、缺失重复和重复 ID 拒绝。真实模型重复运行尚未执行，本课不能报告项目成功率或版本差异。

## 面试考点与踩坑

问：为什么按题聚合？答：同题 Trial 相关，直接当独立题会高估样本量。问：为什么失败 Trial 不能删？答：会造成选择偏差。问：固定随机种子有什么用？答：复现统计抽样，不保证模型确定性。问：区间重叠是否能证明版本没有差异？答：不能；版本对比还需同题配对设计和预设判定规则。
