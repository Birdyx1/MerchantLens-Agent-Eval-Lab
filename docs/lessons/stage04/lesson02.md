## 方法论：集合代表不同决策

评测集是可复用资产。美团白皮书区分黄金样本与已发现问题，并强调线上 Case 回流后先归因，再决定是补样本还是修评测标准；Anthropic 建议从真实失败构造任务，并同时覆盖“应调用”和“不应调用”的情况。以下四集合及入库门禁是**本项目按用户约束作出的工程设计**，不是四家博客共同规定的目录标准。[美团白皮书](https://tech.meituan.com/2026/09/10/Agent-Evaluation-White-Paper-01.html) · [Anthropic Agent Evals](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

| 集合 | 核心问题 | 更新方式 | 当前入库门禁 |
| --- | --- | --- | --- |
| Golden | 同一批已达成共识的题上，新旧版本谁更好？ | 受控轮换，不随线上回流自动变化 | 已仲裁的策划或合成样本 |
| Regression | 发版是否重犯已修复错误？ | 修复后增加派生任务，发版前必跑 | 已仲裁的策划或合成样本 |
| Badcase | 线上出现了哪些离线未覆盖的问题？ | 动态追加，等待归因与复核 | 来源标记为线上回流 |
| Negative | 歧义、脏输入、注入和越权请求会不会突破红线？ | 安全团队策划和复核 | 已仲裁的对抗样本 |

**为什么要物理隔离**：集合承担不同决策，混在一个文件里再靠 `set_type` 过滤，容易因漏过滤、误标或脚本默认值而污染分数。独立目录使批量运行、权限和审计边界更清楚；但目录本身不是安全保证，还要有入库 API、全局唯一 ID 和审计记录。Golden 与 Regression 可以覆盖相似能力，但本项目禁止同一 Task ID 两边复用；由 Badcase 派生回归题时，应建立新 ID 并保留来源关联，不直接移动原文件。

## 本课实现与具体数据流

[四集合目录](../../../eval_sets/README.md)各自有 `tasks/`；[入库器](../../../src/merchant_agent/evaluation/sets.py)执行：读取来源文件 → 写入同集合临时文件 → 用 4.1 的 Schema 与快照哈希校验 → 检查来源和仲裁状态 → 在全局写锁下检查四目录的 Task ID → 完整写入后发布目标文件。失败不留下半条 Task，也不覆盖已有文件。

例如 4.1 的 `store_net_a_001` 仍是 `draft`：调用 Golden 入库会被拒绝。即使将它标记为 `adjudicated` 并通过入库，也不能再以相同 ID 复制进 Regression；若要形成独立回归题，应在仲裁后生成派生 ID。当前四个正式集合目录保持空白，不把示例草稿伪装成黄金资产。

## 验收标准、风险与面试考点

专项测试覆盖四目录分离、草稿拒绝、跨集合重复 ID 拒绝、Badcase/Negative 来源门禁与路径逃逸；全套 pytest **124 passed**。

面试要能解释：为什么 Golden 与 Badcase 更新节奏不同？因为前者服务稳定对比，后者服务发现分布变化。为什么标签字段不够？因为没有存储和写入边界，调用方很容易误用。为什么安全负样例独立？因为安全红线不能被普通任务成功率平均掉。

当前 `provenance` 和 `label_status` 都由提交者填写，入库器只能检查字段值，尚不能验证真实来源、双人标注记录或线上数据已脱敏。4.4～4.5 必须把仲裁证据接入门禁；真实 Badcase 入库须在 9.2 增加脱敏、去重和来源复核。Negative 的安全任务类型将在阶段 8 扩展。Holdout 在 4.6 另建受控位置，不混入这四个常规集合。
