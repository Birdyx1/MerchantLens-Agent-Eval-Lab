## 方法论

反思评测先冻结一次失败观察和模型的下一步输出，再调用真实解析器与 `validate_reflection_decision`。分别记录：输出不符合 JSON/工具契约的 `model_contract`，以及违反反思约束的 `reflection_policy`。合规动作可以是修改参数、换工具或可靠地结束；安全拒绝后继续调用工具必须失败。策略阻断本身是正确行为，不能简单计作失败。期望允许与否必须在运行前标注。

记忆评测检查 LangGraph Checkpointer 的快照：任务身份、Trace 身份、`last_tool_result` 和消息序列中的最新工具观察是否一致。只检查最终答案会漏掉工具观察丢失、线程串数据等问题。2026-11-03 已在 SQLite 持久化检查点上运行跨进程暂停、恢复和 MCP SQL 调用，并用记忆评测器检查恢复后的真实图快照；模型为确定性测试替身，不是线上模型。后续仍需真实模型及多线程并发样本。

## 面试考点与踩坑

- 问：反思策略拒绝了动作算失败吗？答：看预标注的期望；违规动作被阻断应通过安全约束测试。
- 问：`last_tool_result` 已在 State，为什么还看 `messages`？答：模型实际读取消息；两处不一致会使反思基于过时观察。
- 问：如何区分模型问题与 Harness 问题？答：冻结输出重放并单独测试解析和策略，再对照真实运行的 Trace。
- 坑：只用内存快照不能证明进程重启后仍能恢复；真实持久化需另测。
