## 已形成的架构

`ModelPort` 隔离基座模型；LangGraph Harness 负责规划、工具路由、观察循环、反思和预算；MCP 工具层独立；State 与 Checkpointer 负责短期状态和恢复。DeepSeek 通过 Responses 适配器接入，不改图结构。根、模型和工具 Span 共享 Trace ID 并关联父子关系。

## 验收证据

- 固定模型与本地 MCP SQL 的端到端测试证明答案来自真实工具观察，四条 Span 通过当前 Schema。
- 真实 DeepSeek 最小请求返回有效规划 JSON、实际模型 ID 与 token 用量。
- 真实 DeepSeek + MCP SQL 烟雾测试完成两次模型调用和一次工具调用，最终答案包含数据库结果 12000 分；四条 Span 通过当前 Schema 和基础跨记录校验。
- 全套 pytest 115 passed。除 3.1 的学员初稿外，本阶段主要由教师实现，不能作为学员独立编码成果陈述。

## 后续边界

- 单次真实烟雾测试不能代表稳定成功率；需要评测集、多次 Trial 和置信度分析。
- Trace 当前保存原始模型输出和工具数据；JSONL 文件权限已收紧到 `600`，但脱敏、访问控制和保留期仍待实现。
- 通用跨记录校验只覆盖 Trace ID 一致与 Span ID 去重；更完整的轨迹语义在评测流水线中实现。
- 同步 `requests` 在线程中运行，取消协程不会硬停止底层请求；生产环境需更严格的客户端取消与超时策略。
