# 3.9 模型规划 Span

状态：已通过（教师实现，2026-11-02）。

[阶段文档](README.md) · [总计划](../../plan.md)

## 知识点

只看工具调用和最终答案，无法判断规划是否出错。本课在规划节点内记录每次模型调用的独立 `model.plan` Span，关联根 Span，并保存模型版本、原始输出、token 用量、解析后的计划与工具选择。解析失败仍写 Span，原异常继续传播。

## 实践任务

给图构建器注入可选 `trace_path`，在模型规划节点调用前后计时和写盘。成功记录结构化决策，失败记录异常类型，不把无效模型输出当成有效工具动作。

## 验收标准

- 模型 Span 与根 Span 共享 `trace_id`，父 ID 指向根 ID，符合现有 Schema。
- 成功输出及 token 用量可从 Trace 读取；非法 JSON 也留下失败 Span。
- 全套 pytest 通过。

## 面试考点与踩坑

模型 Span 和根 Span 分别由规划节点与运行入口写入，`trace_path` 必须配置为同一个文件。当前原始模型输出可能含敏感数据，生产落地前必须补脱敏与访问控制；模型输入消息和工具选择的独立决策 Span 仍是后续工作。
