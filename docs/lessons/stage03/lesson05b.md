# 3.5b 只读工具的有界自动重试

状态：已通过（教师实现）。

[3.5 总览](lesson05.md) · [故障分类契约](../../contracts/tool_failures.md) · [总计划](../../plan.md)

## 知识点

自动重试应同时满足：操作幂等、故障可能瞬时恢复、尝试次数未超限、步骤预算仍足够。本项目只对 SQL 和网页搜索的**明确调用超时**按原参数自动重试；Python 任意代码、普通 MCP 错误和协议错误交给后续模型反思。重试不能抹掉第一次失败的 Span。

## 实践产物

教师新增 `agent/retry_policy.py` 的 `should_retry_tool`；State 增加 `max_tool_attempts`，默认 2、允许 1～3。LangGraph 行动节点之后按策略进入 `retry` 节点或回到规划节点；`retry` 节点增加 `retry_count`，再次行动沿用同一个 `operation_id` 并递增 `tool_attempt`。规划给出最终答案时保留最后一次工具尝试元数据，便于评测读取。

## 验收标准与结果

- SQL 首次超时、第二次成功：两条 Span 的 `span_id` 不同、`operation_id` 相同，`attempt` 为 1、2；`retry_count=1`。
- 搜索超时在预算内可重试；MCP 错误、Python 超时不自动重试。
- 最大尝试次数为 1 或步骤预算耗尽时不重试；全套 pytest 80 passed。

## 面试考点与踩坑

- “可重试”不等于“所有失败都重试”；`dependency_error` 可能是永久协议错误。
- 失败后成功仍计两次工具调用及一次超时，成本和轨迹指标要保留。
- 本课重试决策由确定性策略执行；模型基于失败观察的反思、修正参数和中止决策在后续小课。
- 预算较大时还需协调 LangGraph 的 `recursion_limit`，留在 3.7 处理。
