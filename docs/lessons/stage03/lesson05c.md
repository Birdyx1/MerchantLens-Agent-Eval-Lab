## 知识点

确定性重试只覆盖少数明确瞬时故障。其他失败作为工具消息进入 State，让模型重新规划：修正参数、换工具或结束。模型的反思决策仍需代码校验；不能通过重新规划绕开同一操作的尝试上限，也不能在安全拒绝后继续调用工具。

## 实践产物

教师在规划节点中加入失败观察提示，并实现 `validate_reflection_decision`。若上一工具结果属于失败类别，规划节点提示模型不要假设失败工具已有有效数据；同一工具同一参数的重复调用被拒绝。`security_rejected` 后只允许结束，不允许继续工具调用。改用其他工具或修正参数会创建新的 `operation_id`。

## 验收标准与结果

- SQL MCP 错误进入 State；模型收到失败提示并改用搜索，形成两个不同操作 ID 的工具 Span。
- Python 程序错误后的原样调用、安全拒绝后的继续调用均在工具执行前被拒绝。
- 全套 pytest：83 passed。

## 面试考点与踩坑

- 自动重试与模型反思不同：前者按固定策略复用同一操作 ID，后者产生新的决策和操作 ID。
- 反思提示不替代校验；提示注入和模型误判仍需安全负样例评测。
- 模型可在失败后给出答案，但目前未校验答案的证据充分性；后续评测层必须识别“无证据却回答”。
- 模型规划输出目前进入 State 消息，但独立模型 Span 尚未写盘，后续补齐。
