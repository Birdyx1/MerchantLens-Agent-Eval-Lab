# 3.8 根 Trace 的终止记录

状态：已通过（教师实现，2026-11-02）。

[阶段文档](README.md) · [总计划](../../plan.md)

## 知识点

工具 Span 的 `parent_span_id` 已指向 `root_span_id`，但只有实际写入根 Span，轨迹才有完整的运行边界。根 Span 在 `run_agent` 结束时追加，记录开始与结束时间、耗时、任务 ID 和终止原因。写入顺序可以晚于子 Span；父子关系由 ID 决定。

## 实践任务

给运行入口增加可选 `trace_path`。正常结束记录图返回的 `termination_reason`；墙钟时限、外部取消和其他异常分别记录 `deadline`、`cancelled`、`error`，并继续传播原异常。异常记录只保存类型，不保存可能含敏感信息的异常正文。

## 验收标准

- 根 Span 符合现有 JSON Schema，使用入口的 `trace_id` 和 `root_span_id`。
- 正常、预算耗尽、超时、取消和内部失败各有明确终止原因。
- 不把未完成调用记作成功；全套 pytest 通过。

## 面试考点与踩坑

`finally` 中的同步写盘可以在取消时保留终止记录，但写盘失败可能覆盖原异常。当前 `trace_path` 是可选入口，后续生产集成须强制配置，并处理写盘失败与并发写入策略。当前根 Span 只覆盖一次 `ainvoke`，检查点续跑需要更高层的任务运行 ID 关联。
