# 2.6a 工具故障分类

## 知识点

Agent 看见工具结果时，需要区分业务空结果、参数错误、外部依赖故障和安全拒绝。否则重试策略与失败归因会错：例如 SQL 查询没有门店记录可正常返回空值，而 Tavily 超时不能伪装成零条结果。此处分类是**本项目的评测契约**，不是 MCP 或 OpenTelemetry 的标准错误码。

## 实践任务

新建 `docs/contracts/tool_failures.md`，只写一张故障分类表。至少覆盖：`success`、`empty_result`、`invalid_input`、`timeout`、`dependency_error`、`security_rejected`。每行写含义、现有工具中的一个例子、是否允许自动重试，以及评测应如何计数。最后补充两条规则：业务空结果与执行失败如何区分；安全拒绝为什么不能由 Agent 自动重试绕过。

本课只设计契约，不改工具代码或 Trace Schema。

## 验收标准

1. 六类都有明确、互斥的判定规则；SQL 空门店与 Tavily 超时归到不同类。
2. 重试建议具体：只对可能恢复的瞬时故障考虑有限次重试；错误参数和安全拒绝不重试。
3. 评测统计保留原始故障类别，不把异常转成 `success` 或 `empty_result`。

## 面试考点与踩坑

- 工具结果、工具异常、Agent 最终答案是三个不同层级。
- `MCP CallToolResult.is_error` 只能表示工具调用失败；业务空结果仍需按业务契约判断。
- 不要把“重试后成功”抹成“首次成功”，后续 Trace 需保留每次尝试。
