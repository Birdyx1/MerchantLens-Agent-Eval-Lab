## 教师代写记录（2026-11-01）

应学员要求，教师实现 `run_python(code, timeout_seconds, max_output_bytes=65536)`：输入校验、创建带随机名称和标签的容器、启动、并发读取两路输出、执行超时、检查退出状态和清理。每路保留输出默认 64 KiB，最多可配置为 1 MiB；诊断文字另行追加。`timeout_seconds` 限制启动后等待程序的时间，Docker 控制命令各有独立超时，因此不是整个调用的总时限。

真实 Docker 测试通过正常输出、Python 异常、超时、输出截断及只读根文件系统写入失败；测试结束时按项目标签查询无遗留容器。三个模拟测试覆盖输出限额、清理失败和创建结果未知。尚未验证网络隔离、资源耗尽、并发或恶意代码逃逸。

2026-11-01 补充：教师增加 SQLite 持久记录，创建前登记名称和随机标签；清理后检查容器是否仍存在。创建结果未知、清理失败或核验失败时保留记录。`reconcile_pending()` 或 `PYTHONPATH=src .venv/bin/python -m merchant_agent.tools.container_recovery` 可核对 300 秒以上的记录，匹配名称与标签后删除并核验；无法找到或验证的记录保持 `unresolved`，因为创建可能晚到。恢复命令须在相应旧执行已停止的情况下由运维定期运行；没有内置常驻调度或自动判断记录何时可安全丢弃。

进一步实测：正常、异常、超时、截断、只读根文件系统、外网连接失败均符合预期；512 MiB 逐页写入触发容器退出 137，Docker 状态报告 `OOMKilled=true`，结果新增可选 `oom_killed` 字段。真实创建带本项目标签的容器后，恢复命令成功删除并核验；七个模拟测试通过。探测不能证明所有网络路径或所有资源限制均可靠。标签用于关联，不是对抗同一 Docker 守护进程上恶意操作者的认证；Docker 本身不是强隔离边界。生产部署仍需专用隔离环境和运维调度。
