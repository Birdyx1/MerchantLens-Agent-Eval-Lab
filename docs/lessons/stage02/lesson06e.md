# 2.6e MCP 搜索调用与证据快照埋点

状态：已通过（教师实现）。

[2.6 总览](lesson06.md) · [总计划](../../plan.md)

## 知识点与架构

搜索结果既是工具返回，也是后续证据评测的输入。客户端调用边界保存本次查询参数与 MCP 返回快照，便于回答“Agent 当时看到了什么”。检索摘要不能证明网页正文支持答案；正文核验另做。

## 实践产物

教师新增 `tracing/observed_search.py` 的 `search_web_observed`：对 `search_web` 的单次 MCP 调用记录参数、结构化快照、原始状态、归一化类别与耗时。成功但结果列表为空归 `empty_result`；MCP 错误或协议结构错误归 `dependency_error`；显式超时归 `timeout`。失败写盘后继续向上传播，不把错误伪装成空结果。

## 验收标准与结果

- 模拟搜索服务走真实进程内 MCP 协议，命中结果与空结果分别落盘。
- 失败调用有独立 Span；没有有效快照时不写假快照。
- 全套 pytest：36 passed。

## 面试考点与踩坑

- `search_snapshot` 是可回放的“当时检索结果”，不是网页正文事实证明。
- 查询词和摘要可能含敏感信息；当前仅用于本地受控 Trace，生产环境需补脱敏与访问控制。
- Tavily 客户端当前合并网络错误与超时；只有明确的超时异常才归 `timeout`，一般 MCP 错误保守归为 `dependency_error`。
