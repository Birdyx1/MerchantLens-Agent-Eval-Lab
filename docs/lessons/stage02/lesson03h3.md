## 知识点

如果创建容器时客户端超时，执行器可能还没有收到容器 ID。创建前由执行器生成名称，可以让后续流程尝试定位这次请求对应的容器。Docker 支持创建时通过 `--name` 指定名称。[Docker create 文档](https://docs.docker.com/reference/cli/docker/container/create/)

名称只是定位线索。超时后 Docker 仍可能继续处理请求；名称本身不能证明容器已创建或已清理，后续要处理核验、归属和竞争条件。

## 实践任务

在 `src/merchant_agent/tools/python_sandbox/python_runner.py` 新增：

```python
def generate_container_name() -> str:
    ...
```

返回格式为 `merchant-eval-` 加 32 位小写十六进制字符的名称，后缀使用 Python 标准库 `uuid.uuid4().hex` 生成。名称由执行器内部生成。

## 验收标准

1. 返回字符串，格式符合 `merchant-eval-` 加 32 位小写十六进制。
2. 多次调用各自生成名称；UUID 随机碰撞概率极低，但不能声称绝对不可能碰撞。
3. 函数不调用 Docker，也不执行用户代码。

## 面试考点与踩坑

- 为什么不能只依赖返回的容器 ID？创建命令超时后，ID 可能没有返回。
- 名称不等于所有权证明；后续清理必须检查容器属于本次执行，并处理名称冲突。
- 教师代写的执行器已将名称传入 `docker create`；创建超时后的延迟回收仍未完成。
