# 2.3f 限制输出内容

状态：已通过。

[阶段文档](README.md) · [总计划](../../plan.md)

建议用时：20—30 分钟。目标：按 UTF-8 字节数截断一段已经获得的文本。

## 知识点

Python 程序可能输出很多内容，Trace 和 Agent 上下文不能无限增长。字节数与字符数不同：中文和 emoji 在 UTF-8 中通常占多个字节。

本课仅处理**已经在内存中的文本**；这不能防止进程产生大量输出耗尽内存。真实执行器必须在读取输出时实施上限，并处理容器终止和清理。

## 实践任务

创建 `src/merchant_agent/tools/python_sandbox/output_limit.py`，实现：

```python
def limit_output(text: str, max_bytes: int) -> tuple[str, bool]:
    ...
```

- `max_bytes` 必须为大于 0 的整数，布尔值不算整数；无效时抛出 `ValueError`。
- 文本的 UTF-8 字节数未超过上限时，原样返回文本及 `False`。
- 超过上限时，返回不超过上限的**最长完整字符前缀**及 `True`；不追加省略号、不产生乱码。
- 输入约定：`text` 是可编码为 UTF-8 的 Python 字符串。

提示：`encode("utf-8")` 可以得到字节；如果截断位置落在多字节字符中，需要处理不完整字符。

## 验收标准

1. `("hello", 5)` 返回 `("hello", False)`；`("hello", 3)` 返回 `("hel", True)`。
2. `("你好", 4)` 返回 `("你", True)`；`("😀a", 3)` 返回 `("", True)`。
3. 0、负数、浮点数和布尔值作为上限时抛出 `ValueError`。
4. 不运行容器；截断标记表示原始字节数是否超过上限。

## 面试考点与踩坑

- 字符个数不等于 UTF-8 字节数；不能只用字符串切片实现字节上限。
- 在已经完整捕获输出之后再截断，无法约束捕获阶段的内存占用。
- 本课函数不是完整沙箱，也没有实现流式读取、超时或容器清理。
