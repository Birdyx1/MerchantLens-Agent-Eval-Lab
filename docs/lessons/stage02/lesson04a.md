## 知识点

Agent 需要记录证据来源，评测时才能检查答案是否有依据。[W3C PROV](https://www.w3.org/TR/prov-o/) 描述了来源与生成活动的关系；以下字段是本项目的简化约定，不是 PROV 标准格式。

检索摘要只是搜索服务返回的文本，可能过期或不准确，不能仅凭摘要证明原网页支持答案。`retrieved_at` 是获取检索结果的时间，不是网页发布时间。

## 实践任务

新建 `src/merchant_agent/tools/search_result.py`，用标准库 `dataclasses.dataclass` 定义 `SearchResult`，所有字段均为必填字符串：

| 字段 | 含义 |
|---|---|
| `title` | 搜索结果标题 |
| `url` | 来源网页地址 |
| `snippet` | 搜索结果摘要 |
| `retrieved_at` | 获取结果的 UTC 时间文本 |
| `provider` | 提供搜索结果的服务名称 |

本课只定义数据结构，不需要调用网络服务或实现字段格式校验。

## 验收标准

1. 可以用五个字段构造实例，并读取对应属性。
2. 可以用 `dataclasses.asdict` 转成字典，并用 `json.dumps` 序列化。
3. 未提供必填字段时构造失败；示例注明是模拟数据。

## 面试考点与踩坑

- 为什么记录 URL 和检索时间？便于追查来源和判断证据时效。
- 为什么摘要不等于已核实的网页证据？摘要可能截断、过期或与网页正文不一致。
- 网页和摘要都属于外部内容，不能把其中的指令直接当成系统指令执行。
