# 2.1 业务数据口径

[阶段文档](README.md) · [总计划](../../plan.md)

建议用时：15—25 分钟。目标：建立一份可用于后续 SQL 工具和评测的模拟订单数据。

## 知识点

Agent 得出的数字是否正确，取决于计算口径。例如，订单有退款时，如果只汇总支付金额，得到的就不是扣除退款后的金额。

本课约定一个简化分析指标：订单净支付金额 = 已支付金额 − 已退款金额。金额使用整数“分”，避免用浮点数表示货币。本口径仅供本项目练习，不作为会计收入确认规则。

## 实践任务

创建 `fixtures/business_data/orders.csv`，手写以下模拟数据：

| order_id | store_id | paid_fen | refunded_fen |
|---|---|---:|---:|
| O001 | A | 10000 | 2000 |
| O002 | A | 5000 | 1000 |
| O003 | B | 8000 | 0 |

假设这些订单均已支付，退款金额都是截至同一个模拟快照时点的累计值。数据均为虚构。

再创建 `docs/contracts/metrics.md`，用自己的话写明：字段含义、金额单位、净支付金额的计算公式，以及门店 A 的净支付金额和计算过程。

## 验收标准

1. CSV 有上述四个表头和三条数据，金额为非负整数，退款不超过支付金额。
2. 文档明确指出数据为模拟值、金额单位为分、退款使用同一快照时点的累计值。
3. 门店 A 的结果只使用 A 的两条订单，计算过程与公式一致。

## 面试考点与踩坑

- 同一个“收入”问题可能有不同业务口径，应在评测前说明公式与时间范围。
- CSV 文件中的数字读取后通常是字符串，后续计算时需要转换类型。
- 本课的订单净支付金额是简化分析指标，不应直接当作会计收入。
