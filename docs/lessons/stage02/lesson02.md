## 知识点

SQLite 将数据保存在本地数据库文件中，无需单独启动数据库服务。Python 的 `sqlite3` 模块可以建表和执行 SQL；插入数据后需要提交事务。[Python 官方文档](https://docs.python.org/3/library/sqlite3.html)

本课负责准备测试数据；被测 Agent 的只读权限及工具调用放在 2.2b，不应把本课的写入程序当作只读工具。

## 实践任务

创建 `src/merchant_agent/tools/sql/init_orders_db.py`，自行实现：

```python
def create_orders_db(csv_path: str, db_path: str) -> None:
    ...
```

输入是上一课的 `orders.csv` 与一个**尚不存在的数据库文件路径**；其父目录假设已经存在。创建 `orders` 表并导入 CSV 的全部订单。列名与 CSV 一致，`order_id`、`store_id` 用 TEXT，`paid_fen`、`refunded_fen` 用 INTEGER；`order_id` 为主键。

如果 `db_path` 已存在，抛出 `FileExistsError`，不能覆盖。练习和测试使用临时目录；不要对已有真实数据库执行。可用标准库 `csv`、`sqlite3` 和 `pathlib`。

提示：`csv.DictReader` 读到的金额是字符串，需要转成整数；插入时用 SQL 的 `?` 占位符绑定数据，提交后关闭连接。

## 验收标准

1. 新数据库中 `orders` 表包含上一课三条记录，金额存储为整数。
2. 门店 A 的净支付金额查询结果为 12000 分。
3. 已存在目标文件时抛出 FileExistsError，原文件内容不变。
4. CSV 不存在或导入出错时，错误传给调用方，不伪装成功；使用临时目录验证。

## 面试考点与踩坑

- 参数化 SQL 将数据和 SQL 结构分开；不要拼接输入生成 SQL。
- `commit` 与关闭连接职责不同。
- 本课假设单进程使用目标路径；并发创建的原子性和失败后清理留待后续工程化处理。
