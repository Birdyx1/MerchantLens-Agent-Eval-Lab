## 结论与使用边界

本轮整理 10 个岗位样本，来源包含企业招聘官网、BOSS直聘、智联招聘、牛客及招聘聚合站。它们不是随机样本，不据此计算市场占比或宣称某框架是行业必备。

从已读岗位判断，学习应优先覆盖：编程与数据处理、Agent运行机制、任务与数据集设计、自动评分、批量评测、轨迹归因、版本回归和实验可信度。具体品牌工具随岗位方向变化。该优先级是调研后的建议，不是招聘方统一标准。

证据口径：

- A：企业官方招聘页正文或其搜索索引；部分动态页通过浏览器渲染核验。
- B：招聘平台岗位详情，记录发布主体及页面状态，不等同于企业官网核验。
- C：BOSS公开列表摘要；详情被验证页阻挡，只记录可见内容。
- D：第三方转载，技术栈仅作线索；未获得原站全文核验。
- “未列出”表示本次可见材料没有提到，不能解释为岗位不要求。
- 岗位可访问、按钮可见不保证招聘名额仍然有效；只在页面明确标记时记录结束状态。薪资不作市场估值。

## 4. 面向当前 agent-eval 学习项目的建议

以下是根据JD归纳的实现顺序，不是对当前代码完成度的审计，也不是招聘方指定架构：

1. 先完成 Python 评测主流程：任务集 → 执行Agent → 记录轨迹与结果 → 评分 → 汇总。
2. 补充数据集、模型、Prompt、工具配置和评分器的版本信息，确保同一配置可复跑。
3. 将结果校验与过程校验分开：除最终回答外，检查工具、参数、状态变化、重试与恢复。
4. 加入规则评分与模型评分，并用人工参考样本检查Judge误判；记录无法判定的样本。
5. 提供版本对比、失败分类、时延与成本报告；重复运行以观察波动，避免只报告一次总分。
6. 加入容器运行、超时与资源限制，并接入持续回归；求职Infra方向再深入Kubernetes与分布式调度。
7. 按目标选择一个外部Benchmark或框架做接入，说明任务格式、环境、打分、失败原因与复现条件。

优先顺序建议：Python/数据处理 → Agent机制 → 评测集与评分 → 轨迹归因与实验分析 → 容器与CI → 专项Benchmark/平台扩展。现有面试资料可结合[资料索引](agent-eval-sources-2026-10-31.md)、[面试指南](agent-eval-interview-guide.md)阅读；它们与本次招聘JD属于不同证据类型。
