# 阶段 6：三次真实裁判投票试点（2026-11-03）

## 方法

在[已完成人工双标的六条虚构边界挑战](judge_challenge_calibration_2026-11-03.md)上执行[三裁判面板](../../src/merchant_agent/evaluation/judge_panel.py)。每条回答发起三次独立 API 调用，使用三个不同模型实例和裁判 ID，但**均为 DeepSeek `deepseek-flash` 同一模型家族、同一固定 Rubric**。三票齐全且至少两票相同才输出多数结论；三方各一票或调用失败进入人工复核。Code 分数未由面板修改。

调用前固定挑战集、Rubric、面板源码、单裁判源码及真人双标校准记录摘要。原始逐票分数、理由、模型 ID、token 和运行状态保存在私有记录 `runs/judge_panels/1e96e6df33824bd08cd367b212f6610c/results.json`。运行器见[真实面板挑战](../../src/merchant_agent/evaluation/live_judge_panel_challenges.py)。未使用真实业务 Trial 或 Holdout。

18 次调用均返回有效票；六题都形成多数结论，无 `disagreement` 或 `incomplete`。总 Judge token 为 **6,799**；先前同六题单次 Judge 试点为 2,168 token，本次约 **3.14 倍**。该对比只描述本次 token 用量，不是稳定成本估计。

## 解释与缺口

这验证了三票记录、多数结论及成本采集在真实 API 上可运行；**不能宣称三名独立裁判**。同模型家族和提示词可能产生相关错误，3/3 同票不等于正确；六题本身由人编写、边界清楚。由于没有真实分歧或 API 失败，本次没有真实触发人工复核分支，其逻辑仅由单元测试覆盖。下一步应使用异构裁判或更难的自然失败样本，并保留分歧案例做人工复核。
