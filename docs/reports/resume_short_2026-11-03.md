# 投递版简历（2026-11-03）

**商家经营分析 Agent 开发与自动化评测平台**（个人项目）

**技术栈：** Python、LangGraph、MCP、SQLite、pytest、FastAPI

- **Agent 开发：** 基于 LangGraph 实现「规划 → 工具调用 → 观察 → 再规划」ReAct 循环，接入 7 个门店指标 MCP 工具及只读 SQL 查询，支持多门店计算、NL2SQL 与分层经营归因；实现结构化规划、答案解析容错和步数预算，并通过 SQLite `mode=ro` 限制数据库写入。
- **评测资产设计：** 构建金额计算、多门店求和、NL2SQL、分层归因及对抗输入 5 类任务，绑定 Rubric、环境数据哈希与评测侧 Oracle；设计四类评测集合与独立 Holdout，提供数据校验清单和复现命令，支持任务及实验版本追溯。
- **结果与过程评测：** 使用代码规则校验金额、列名、浮点容差及结果集，以 LLM 裁判评估回答清晰度与归因合理性；结合 Trace 检查工具调用、执行顺序和越权行为，分别记录评分依据，辅助定位结果错误、流程异常及安全违规。
- **公开基准对照实验：** 接入 BFCL、BIRD SQLite 固定子集，冻结 40 道任务，完成双模型工具调用对比与同模型直接生成 SQL / ReAct 对照，共 240 个 Trial；统计正确率、三次运行一致性、耗时及 Token 用量，按题目配对 Bootstrap 分析差值，并实现逐条记录核验与离线重评分。
- **自动化回归与门禁：** 实现批量 Trial、指标聚合、同题双批次对比及报告生成；安全违规触发一票否决，通过率下降或安全退化触发 critical 告警。407 项 pytest 测试通过，覆盖契约、裁判、只读隔离、答案泄漏防护、门禁及复现检查。
- **缺陷定位与修复：** 通过执行轨迹定位并修复长 SQL 截断、重复验证耗尽步数等问题，完善规划解析与提示约束，本地提示注入专项由 2/4 提升至 4/4。
- **数据飞轮机制：** 围绕「异常发现 → 脱敏去重 → 标注复核 → Badcase 入库 → 修复回测 → 派生回归」实现样本治理模块；扫描 147 个 Trial，识别 24 个异常 Trial，去重形成 14 条候选。开发标注工作台，支持候选唯一、标注不可覆盖及一致/分歧状态流转，仅放行判断一致且确认为真实问题的候选，并提供修复前后校验与回归任务派生能力。

项目范围：经营题基于合成数据；公开基准为子集适配实验，非官方全量榜单成绩；14 条候选尚未完成人工独立标注及入库回测。

投递建议：测试开发方向优先展示自动化回归、缺陷定位和门禁；Agent 评测方向优先展示评测设计、公开基准对照与裁判实现。上面的测试数和实验规模均为截至本版本的实测记录。
