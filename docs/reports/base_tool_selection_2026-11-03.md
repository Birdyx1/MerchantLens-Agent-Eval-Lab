# 阶段 7.1：多工具自主选择探针

## 方法

旧工具探针直接给出正确动作。本次先冻结[四道合成题和期望](../../fixtures/base_tool_selection_v1.json)，模型只收到工具定义、通用 JSON 契约和题面，不收到期望标签。任务包括两个门店查询、固定短语检索及指定 Python 表达式；工具和参数由模型选择。Python 内容通过 AST 比较，不执行生成代码。

DeepSeek 与 GLM 使用各自接口默认解码配置，每题一次，未调用真实工具。输入、输出和用量私有记录：`runs/base_tool_selection/6a10084ab7c944f4aa541ebe9eb0ca0f/results.json`。评分器随后修正：非法 JSON 的工具及参数记为未知，而不是误记为错误；重评分记录 `rescored.json`，原始记录保留。

## 结果

| 模型 | 输出契约 | 工具及参数通过 | 总 token |
| --- | ---: | ---: | ---: |
| DeepSeek | 4/4 | 4/4 | 1,109 |
| GLM | 2/4 | 2/4 可判定且通过 | 1,496 |

GLM 两道门店题将 JSON 放入 Markdown 代码块，严格解析失败；人工查看代码块内的工具和门店参数与期望一致，但按原契约这两题仍不通过，不能统计为严格通过。它与此前四格实验使用的 GLM JSON 模式不同，所以不能把此次差异简单归因于模型能力。

两模型各四题、每题一次，且题面相对直接，不能代表真实业务的工具选择准确率。后续应增加多工具歧义、错误参数与重复运行，并保持模型接口与解码配置一致可追溯。
