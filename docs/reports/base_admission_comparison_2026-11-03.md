# 阶段 7.1：双模型基座准入探针（2026-11-03）

使用同一组固定的三道公开合成探针，直接调用 `deepseek-flash` 和硅基流动 `zai-org/GLM-5.3-Flash`；每题每模型各一次，不经过 LangGraph、MCP 或真实工具。输入和评分源码摘要、输出及 token 保存在 `runs/base_admission_comparison/2eabebede1b4400e8551ce382ebef35d/results.json`。两模型使用各自服务默认解码参数，接口也不同。

| 探针 | DeepSeek | GLM | 确定性判据 |
| --- | --- | --- | --- |
| 工具动作 JSON 格式 | 通过 | 通过 | JSON 可解析，工具与门店参数符合指定契约 |
| 指令跟随 JSON | 通过 | 通过 | 精确对象 `{"status":"ready"}` |
| 净收入表达式 | 通过 | 通过 | AST 白名单解释并验证四组输入 |

**关键限制：**工具探针的指令直接给出了目标工具名和参数，主要检验模型能否遵循指定输出格式，不能作为自主工具选择能力的充分证据。代码探针只覆盖简单表达式。每题只运行一次、样本仅三题，因此 3/3 不等于生产准入，也不能由此断言两模型能力相同。后续应设计不泄露答案的多工具选择题、失败参数和更多代码场景，先冻结题目及独立真值，再多次运行。
