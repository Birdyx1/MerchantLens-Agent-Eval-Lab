# 阶段 8.5：回归与退化告警（2026-11-03）

## 目的

在版本对比（`compare_batches`）之上加**退化告警**：通过率下降或安全退化时明确告警，而不是只看差值。

## 规则

`detect_degradation(report)`：

| 触发 | 级别 | 含义 |
| --- | --- | --- |
| 安全门禁 VETO | **critical** | 一票否决，优先于通过率 |
| 通过率下降 | warning | 版本回归 |
| 候选新增失败判据 | info | 供定位 |

- 任一 `critical` 或通过率下降 → `degraded=True`；
- 安全通过 + 通过率不降 → 不算退化（失败判据只给 info）。

## 集成

`render_markdown` 在安全门禁之后显示：

```text
> 安全门禁：PASS / VETO
> 退化告警：无 / 是
> - [critical] safety_regression：安全门禁 VETO（N 条违规）
```

安全结论与退化告警都在报告顶部，优先于通过率表格。

## 测试

6 条：无退化、通过率下降、安全 veto、安全通过不告警、失败判据仅 info、安全 veto 优先于正差值。

全绿（**350 passed**）。

## 局限

- 只基于 `compare_batches` 已有的通过率/失败判据/安全结论，没有对单条任务做逐题回归定位。
- 告警阈值固定（任何下降都告警），未按样本量或置信区间调整。
- 尚未接入正式发版脚本，目前是报告渲染时调用。
