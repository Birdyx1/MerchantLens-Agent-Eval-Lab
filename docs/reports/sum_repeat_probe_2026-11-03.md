# 阶段 6/7：多步合计题重复运行与失败率探针（2026-11-03）

## 目的

[多步探针](multi_step_probe_2026-11-03.md) 只做了单次运行，无法估计失败率。本次对 6 道 `store_net_sum` 合计题各重复 3 次（共 18 个 Trial），目标：估计参数提取错误的复现率、产生 Judge 0/1/2 分样本。

## 方法

- 教师代写入口：`src/merchant_agent/evaluation/live_sum_repeat_probe.py`。
- 6 道 `draft` 合成探测题 × 3 次重复 = 18 个真实 Trial；每题独立数据库与 Trace。
- Code Judge（3 条合计判据）+ LLM 清晰度裁判。
- 统计时**严格区分「运行故障」与「模型失败」**：`trial_status != completed` 计为故障，不计入模型失败率。
- 私有记录：`runs/sum_repeat_probe/cfb44b0d8a2e4db0bd0d1c1e260db78c/results.json`；重算汇总：同目录 `aggregate_recomputed.json`。

## 结果：模型失败率 0，运行故障 27.8%

| 指标 | 数值 |
| --- | ---: |
| 总 Trial | 18 |
| 成功完成 | 13 |
| 成功完成中通过 | **13/13 = 100%** |
| 模型失败（完成但答错） | **0** |
| 运行故障（error） | 5 |
| 故障率 | **27.8%** |
| Judge 分布（完成 Trial） | 2 分 × 13 |

按题：前 4 题（ab / ab_id / de / de_id）各 3/3 全部完成并通过；vw 完成 1 次、故障 2 次；xy 故障 3 次。

## 关键发现

1. **多步合计题在成功运行时全对**：13/13，`ab` 题早先那次「门店A」参数提取错误**没有复现**（本次 3/3 通过）。这进一步确认那是偶发的模型输出随机性，不是稳定缺陷；在有效样本内**没有产生新的模型失败**。
2. **真正的缺口是运行稳定性，不是模型能力**：5 个失败全部是 `SSLError`/`ConnectionError`。Trace 显示 `vw r1` 第一次查询成功后、第二次模型调用 `SSLError`；`vw r2` 直接 `ConnectionError`。连续运行 18 个 Trial 触发网络/连接失败，与 D 题历史 ConnectionError 同类。
3. **这批故障不能算作失败样本**：`trial_status=error` 且 `final_answer=None`；Judge 对缺失回答给 0 分，但这代表"没答"而非"答错"，不能用于 Judge 0/1 分校准。

## 局限

- 5/18 故障使有效样本只有 13 条，且故障集中在后两题（vw、xy），导致按题样本极不均匀。
- 仍然**没有产生真正的 0/1 分模型回答**（唯一一次是早先 ab 题的参数提取错误）。Judge 校准所需的失败/边界回答覆盖仍不足。
- 18 个 Trial 规模太小，即便成功完成全对，也不能推断多步能力的稳定通过率。

## 下一步

1. **查清 27.8% 网络故障的触发条件**（是否短时限流、是否需要退避重试），并在稳定网络下重跑 vw/xy，补足有效样本。
2. 为重试增加可观测记录：区分「模型失败」「工具失败」「连接失败」，避免把环境噪声混进能力指标。
3. Judge 0/1/2 分校准仍是缺口：现有自然失败样本只有 1 条偶发参数错误，需要更多稳定可复现的失败来源（或明确使用受控挑战样本并如实标注）。
