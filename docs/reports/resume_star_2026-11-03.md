# 简历（STAR 法则，2026-11-03）

> 仅包含有真实证据的内容。未验证的部分不出现在简历里。

## 项目经历

**商家经营分析 ReAct Agent 评测体系**（个人项目，2026）

### Situation（背景）

面向商家经营的 Agent 需要回答「门店净收入」「品类退款率」「为什么某月下降」这类问题。这类系统的问题在于：**模型说得出答案，但没人能证明它是对的还是蒙的**——工具调用是否有效、结论是否有证据、遇到歧义或注入会不会越权，都缺少可复现的度量。

### Task（目标）

从零搭建一套可复现的评测体系，覆盖：

1. 多题型（单门店指标、多门店求和、NL2SQL、分层归因）；
2. 安全对抗（歧义/脏输入、提示注入、危险动作）；
3. 数据飞轮（异常回流成新任务）；
4. 发布门禁与标准报告。

要求每条结论都有 Trace 证据，不允许「看起来对」。

### Action（行动）

- **Agent 侧**：LangGraph 实现「规划 → 工具 → 观察」循环；`run_sql` 只读执行（SQLite `mode=ro`），按前缀分类拒绝写/DDL，返回结构化结果集；为长 SQL、歧义输入、注入请求分别加了提示词与格式容错。
- **评测侧**：四类集合物理隔离 + 密封 Holdout（哈希锁定）；代码裁判 + LLM 裁判双轨；NL2SQL 做列名/容差/结果集对齐；归因题同时评「关键事实」与「查询证据」。
- **安全侧**：实现 8.1a 歧义/脏输入、8.2 提示注入、8.3 危险动作的契约与硬约束裁判；8.4 安全一票否决门禁；8.5 回归与退化告警，并把安全结论置顶到报告。
- **数据飞轮**：异常识别（5 类规则）→ 脱敏去重 → 标注工作台（候选唯一、不可覆盖、状态机）→ 入库门禁 → 修复回测与派生回归。
- **工程修复**（真实发现的问题）：浮点容差自相矛盾、大小写列名不匹配、长 SQL 被截断、注入请求反复验证耗尽步数、对抗 marker 过宽导致误判。

### Result（结果）

- **389 个测试**通过，覆盖契约、裁判、门禁与复现；
- NL2SQL 3 题、归因 4 题、对抗 12 条真实运行，修复截断与步数问题后 4/4 通过；
- 安全门禁 12 条汇总：修复 2 条违规后 **PASS**；
- 异常识别在 **147 个 Trial** 中识别 24 个异常，脱敏去重为 **14 条候选**；
- 复现清单 **8 个数据文件**哈希校验可复现；
- 真实修复了 5 类工程缺陷，每一类都有对应测试与报告。

## 技能清单（真实使用）

- **语言/框架**：Python 3.13、LangGraph、FastAPI、SQLite、pytest、Streamlit（原型）；
- **Agent 工程**：ReAct 循环、MCP 工具、Trace/Span 观测、提示注入防御、只读 SQL 沙箱；
- **评测工程**：题型契约、代码裁判、LLM 裁判、双人标注一致性、安全门禁、复现清单；
- **数据工程**：异常识别、脱敏、去重、来源标记、Badcase 入库门禁。

## 诚实边界（面试会问，主动说）

- 对抗样本各 4 条、单次运行，**不构成统计显著**；
- 数据飞轮的 14 条候选**尚未真人标注**，没有真实入库与回测；
- 语义复核多为 **LLM 裁判**，不是人工；
- UI 是原型，不是正式产品；
- 全部数据为合成数据，**不能写成线上生产成绩**。
