# 简历（STAR 法则，2026-11-03）

> 仅包含有真实证据的内容。未验证的部分不出现在简历里。

## 项目经历

**商家经营分析 Agent 开发与自动化评测平台**（个人项目，2026）

### Situation（背景）

面向商家经营的 Agent 需要回答「门店净收入」「品类退款率」「为什么某月下降」等问题。除验证最终答案，还需要检查工具选择与参数、归因证据和安全约束，并通过固定任务对比模型或执行配置变化的影响。

### Task（目标）

从零搭建一套可复现的评测体系，覆盖：

1. 多题型（单门店指标、多门店求和、NL2SQL、分层归因）；
2. 安全对抗（歧义/脏输入、提示注入、危险动作）；
3. 数据飞轮机制：异常发现、样本治理、标注复核、入库及回归派生；
4. 发布门禁与标准报告；
5. 公开 Benchmark 子集对照与重复运行稳定性。

要求运行记录可追溯、评分可复算；将模型失败、评分契约问题和观测缺口分开记录，不把单次小样本通过率外推为生产表现。

### Action（行动）

- **Agent 开发**：基于 LangGraph 实现 ReAct 循环，接入 7 个门店指标 MCP 工具及 `run_sql`；实现结构化 JSON 规划、答案解析容错和步数预算。业务 SQL 工具使用 SQLite `mode=ro`，按语句前缀分类拒绝写入和 DDL，返回结构化结果集；不将此前缀规则声称为完整 SQL 安全解析器。
- **领域评测**：覆盖单门店、多门店求和、NL2SQL、分层归因及对抗输入；绑定题目、Rubric、环境数据和 Oracle；设计四类集合与独立密封 Holdout，用哈希检查快照变化。将结果与过程作为两个评测维度：代码校验金额、列名、容差及结果集，LLM 评估清晰度和归因合理性，Trace 检查工具调用及越权行为。
- **公开基准**：在模型运行前冻结 BFCL 20 题、BIRD SQLite 20 题，记录数据提交版本、参考答案与评分源码哈希。BFCL 用统一 JSON prompting 对比 DeepSeek、GLM；BIRD 用同一 DeepSeek 对比直接生成 SQL 和实验专用 ReAct SQL 循环，每单元每题 3 次，共 240 个 Trial。BIRD 输入含公开 evidence 和 Schema，参考 SQL 不进入模型上下文。
- **评分与对照**：复用 BFCL 官方 Python checker 原始函数体及 BIRD 官方 EX 函数；BFCL 隔离无关依赖并适配 JSON 调用数组，未运行官方完整模型 handler。BIRD 用完整结果行集合评分，预览截断不参与评分；通过只读连接、授权器、查询中断及行数上限约束执行。报告失败分型、重复一致性、耗时、Token 和调用次数，按题目配对 Bootstrap，失败和异常不从分母删除。
- **安全与回归**：实现歧义/脏输入、提示注入、危险动作的契约及硬约束检查、安全一票否决和退化告警，将安全结论置顶报告；缺失证据不默认通过。
- **数据飞轮机制**：围绕「异常发现 → 脱敏去重 → 标注复核 → Badcase 入库 → 修复回测 → 派生回归」实现各环节模块。从 Trial 与 Trace 识别任务未完成、预算耗尽、工具失败、安全拒绝和无工具证据的金额回答；对密钥、手机号和邮箱脱敏，按任务及异常类型集合去重并保留重复次数。工作台支持候选唯一、标注不可覆盖及 pending → one_label → agreed/disputed 状态流转；入库门禁只放行 agreed 且确认为真实问题的候选。实现修复前失败/修复后通过的校验，以及保留评测契约和来源引用的回归任务派生。实际验证推进到 147 个 Trial → 24 个异常 Trial → 14 条候选；候选尚未完成人工独立标注，不能声称入库回测闭环已完成。
- **工程修复**（真实发现的问题）：浮点容差自相矛盾、大小写列名不匹配、长 SQL 被截断、注入请求反复验证耗尽步数、对抗 marker 过宽导致误判。

### Result（结果）

- **407 项 pytest 测试通过**，覆盖契约、裁判、SQL 隔离、答案泄漏防护、门禁与复现。
- 本地合成题专项：修复后 NL2SQL **3/3**、归因 **4/4** 通过；提示注入专项由 **2/4 提升至 4/4**。这些是小样本观测，与公开 Benchmark 分开报告。
- 安全门禁：12 条样本汇总，修复 2 条违规后通过；不外推整体安全性。
- BFCL 固定子集：DeepSeek **53/60（88.3%）**，GLM **49/60（81.7%）**；主要差异在不应调用工具的题目。GLM−DeepSeek 配对差值 −6.7 个百分点，95% Bootstrap 区间 [−20.0, +3.3]，包含 0。
- BIRD 固定子集：直接生成 SQL **22/60（36.7%）**，ReAct **17/60（28.3%）**；ReAct 有 20 次格式错误。差值区间包含 0，本次没有证据证明增加 ReAct 循环带来稳定提升。每题三次均成功分别为 **6/20、2/20**，可区分偶尔成功与重复稳定性。
- 240 条运行记录审计通过：224 条可评分记录离线重算一致，16 条响应/适配异常保留为失败；来源和数据库在运行前后哈希一致。
- 领域异常扫描：**147 个 Trial → 24 个异常 Trial → 14 条候选**；原领域实验另有 **8 个数据文件**的复现校验清单。两组实验规模与来源不混用。

## 技能清单（真实使用）

- **语言/框架**：Python 3.13、LangGraph、FastAPI、SQLite、pytest、Streamlit（原型）；
- **Agent 工程**：ReAct 循环、MCP 工具、Trace/Span 观测、提示注入防御、只读 SQL 沙箱；
- **评测工程**：题型契约、代码与 LLM 裁判、轨迹评测、公开基准子集适配、配对对照、按题目 Bootstrap、标注流程、安全门禁、离线重评分；
- **数据工程**：异常识别、脱敏、去重、来源标记、Badcase 入库门禁。

## 诚实边界（面试会问，主动说）

- 对抗样本各 4 条、单次运行，**不构成统计显著**；
- 数据飞轮的 14 条候选**尚未真人标注**，没有真实入库与回测；
- 语义复核多为 **LLM 裁判**，不是人工；
- UI 是原型，不是正式产品；
- 领域经营题基于合成数据，新增 BFCL/BIRD 为公开开发基准子集；两者均不能写成线上生产成绩。
- BFCL 未覆盖多轮与完整 Agentic 类别，使用项目 JSON prompting 适配，不能称为原生函数调用或官方全量成绩。
- BIRD 只选五个较小数据库；ReAct 为实验专用 SQL 循环，不能把此结果直接当完整 LangGraph Agent 的公开基准成绩。
- 16 条适配异常只记录 ValueError，未保存原始 HTTP 响应，不能进一步归因为网络错误或截断；其真实 Token 用量未知。
- 同一 AI 会话生成的 reviewer_one / reviewer_two 记录不是两位真人独立标注，不能充当人工一致性证据。

## 面试时可讲的实验结论

“我没有预设 Agent 循环一定更好。在固定 BIRD 子集上，直接生成 SQL 为 22/60，ReAct 为 17/60，后者的主要失败来源包括格式协议违规。两者差值区间包含 0，所以我没有声称显著提升，而是用逐题轨迹和失败分型确定后续应优先验证结构化输出与工具协议。”

“公开基准用于补充外部验证，自建经营题用于验证具体业务约束。我分别记录两者的数据来源、评分规则和结果，避免用小型合成题的全通过代替跨数据库或多轮能力。”

“数据飞轮的目标是让运行中暴露的问题成为后续评测资产。异常检测只负责发现值得复核的证据，不直接把它判为真实 Badcase；经过脱敏、去重和独立标注，再由入库门禁控制转化。后续修复应先验证原失败任务能通过，再派生为回归任务保护已有能力。目前 14 条候选还没有完成人工独立标注，实际闭环尚未完成。”
