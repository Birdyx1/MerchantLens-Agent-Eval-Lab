## 为什么重新准备数据

D/E/F/G 共用同一份已用于开发试跑的订单 CSV，因此它们只适合试点 Golden/Regression，不能充当未见题 Holdout。本次另外冻结一份订单快照，放在 Git 忽略的 `holdout/fixtures/`，两道草稿放在 `holdout/drafts/`。二者与四个正式集合物理分离，且未进入 few-shot 或模型运行。

## 标注与封存

两位真人分别通过 `annotation_cli show` 查看盲标包，根据快照独立计算后提交；不要打开含 Oracle 的草稿 JSON，也不要看对方记录。两份标注比较后，一致则形成共识，有分歧须第三人仲裁；再由冻结 CSV 独立复算，最后通过 `HoldoutStore.register` 放进 `holdout/tasks/`。标注者 ID 仅是本地记录标识，不能技术证明真实身份和独立性。

入库时记录 Task、环境、Rubric 和标注摘要。封存后不用于提示词、路由、模型参数或工具实现调试，也不将题面放进 few-shot。只在预先约定的版本验收点运行，开封后记录使用的模型/Harness 版本和运行时间。若开发侧看过答案并据此调整系统，该批题须退役，不能再称未见题。

**限制**：`.gitignore` 和文件权限只能提供本机基础隔离；项目所有者和本机管理员仍可读取草稿与答案。严格团队 Holdout 还需独立账号、访问审计、加密存储和独立保管人。两题规模也不足以估计稳定泛化能力；本次只验证预留流程。
